# 01_Plan 示例样本

> **说明**: 这是一个半空白示例，用来展示 `01_Plan.md` 常见可以写到
> 什么颗粒度。后续使用时，请按当前主题自由增删章节、调整顺序，
> 不要求逐段照抄。

> **适用场景**: `/write` / `/interview` 进入 Stage 1 后，主编需要把素材、
> SEO 与事实核查整合为一份可供下游消费的策划案。

> **提醒**:
> 1. `前置分析卡` 是 Stage 1 步骤 0 的产出，主编只读一次旧文索引即完成所有预写判断。
> 2. `SEO 决策卡` 是下游 Stage 2 / Stage 3 的唯一 SEO 输入源。
> 3. `人机边界卡` 用来保证不虚构 星辰 的第一手经历。

## 1. 前置分析卡

### 文章类型

- 类型: （现象解读型 / 方法论分享型 / 产品体验型 / 调查实验型 / 工具分享型 / 读书心得型）
- 大纲重心说明: （根据所选类型，说明本次大纲侧重什么）
- 若为读书心得型：书中观点的准确传达是第一优先级；个人体感为加分项而非强制项

### 内容支柱

- 支柱: （微习惯实验 / 正念冥想笔记 / 教练体感 / 读书分享）
- 跨支柱处理: 若文章跨多个支柱，选主导情绪的那个
- 用途: 下游视觉导演据此选择侧边栏底色，见 `wechat-director/references/sidebar_design_system.md`

### 选题质检（四维）

- 好奇感: 强 / 中 / 弱
  具体钩子: （有没有一个具体场景、反常识细节或真实问题，让读者想继续看下去？）
- 信息增量: 强 / 中 / 弱
  新增价值: （读者看完能不能多知道一点事实、方法、经验或判断？）
- 共鸣感: 强 / 中 / 弱
  对应读者处境: （这件事是否能连接到读者自己的处境，而不只是作者自说自话？）
- 读者收益: 强 / 中 / 弱
  一句话: 读者读完这篇文章，能带走______。
- 结论: 继续 / 补素材 / 调整角度
  原因: （至少满足两项即通过）

### 价值主张卡 ★ v6.0.0

4 个字段，写入 `01_Plan.md`。这是全文的北极星——大纲和标题都从这里出发。

```
- 写给谁: （张建国 / 陈思远 / 林小满 / 苏青 / 全向）
  （全向时，"什么场景下""什么需求"可拆 2-3 句，每个画像一句）
- ta 在什么场景下: （一句话，具体的处境/时刻）
- 满足 ta 什么需求: （一句话，ta 在这个场景下的内在驱动力）
- 读完能带走什么: （一句话）
```

> 画像判断参考 → `knowledge/reader_profiles.md` 画像-文章天然匹配速查表。

### 旧文延续性检查（三维）

- 主题避让: （是否与已发布文章撞题或角度重叠；对照 `published_article_index.md`）
- 人物/事实一致性: （同一事件、人物、数据在旧文中的描述，本文是否一致）
- 读者叙事弧: （新文章在读者累计阅读中的位置——延续 / 补充 / 新开方向）

### 读者价值声明

（一句话）读者读完这篇文章，能带走______。

## 2. 素材摘要

- 这篇文章真正想讲的，不是「又一个效率工具」，而是「为什么很多人
  一边在记笔记，一边在逃避真正的思考」。
- 当前素材里最有价值的部分，是作者自己的体感、一个朋友的对照案例，
  以及两段带情绪的原话。
- 需要删掉的部分：纯概念解释、重复的工具功能介绍、泛泛而谈的行业判断。

## 3. 人机边界卡

- 星辰 原话与亲历:
  - 自己过去如何记笔记、何时发现笔记失效
  - 原始素材中的情绪表达和具体动作
- AI 可辅助:
  - 补充知识管理、PKM、工具生态的背景信息
  - 帮忙找类比候选和结构建议
  - 做事实核查与表达润色
- 禁止虚构:
  - 星辰 没说过的使用经历
  - 未出现过的朋友案例
  - 未验证的数据或工具结论

## 4. SEO 决策卡

- 状态: weak-signal
- 标题主词: 知识管理
- 正文/摘要辅助词: PKM、笔记系统
- Tags 候选: 知识管理, PKM, 笔记系统
- 放置计划:
  标题可轻量吸收「知识管理」；正文开头自然出现一次「PKM」；

## 5. 核心论点

这篇文章要成立，不靠讲工具有多强，而靠讲一个更扎心的判断：
很多人不是不会整理信息，而是不愿意面对自己到底想留下什么。

## 5.5 ✨ 闪亮点 & 📍 落点

### ✨ 闪亮点

> 这篇文章最亮的那个瞬间/画面/洞察是什么？（1-2 句）

（必须具体——一个画面、一个洞察、一个转折瞬间。禁止写"这篇文章干货很多"。）

### 📍 落点

> 读者读完最后一段，带走什么感觉？

（方向性描述，不是口号。例："可以试试这个方法""被理解""重新看待自己那个处境"。）

## 6. 结构大纲

### 开头钩子

- 从一个真实动作切入：明明记了很多笔记，但回头几乎没有一条能改变决策。
- 快速提出冲突：问题不在工具不够好，而在我们把"记录"当成了"思考"。

### 中段展开

- 第一层：讲自己的经历，说明以前为什么会沉迷收集。
  回扣句: 所以问题不是我少了一个工具，而是我一直在逃避判断。
- 第二层：引入一个外部对照或朋友案例，说明这不是个体问题。
  回扣句: 换到别人身上也一样，信息保存得越多，不代表行动越清楚。
- 第三层：提出真正的判断，解释为什么"笔记越多，反而越空"。
  回扣句: 真正有价值的笔记，最后应该能改变一个决定。

### 结尾落点

- 回到作者现在的做法：删掉大部分无效记录，只保留能改变行动的内容。
- 留一个可转发的余味句，而不是说教式总结。
- 呼应设计：回到开头「记了很多，却用不上」的具体场景，但视角从焦虑
  变成从容取舍。
