# wechat-daily「生活中的美好」轻量流程 v2.5.1

> 角色：轻写手（复用冰清语感，不走 6 角色协同）
> 触发：`/daily`，素材现成就跑，没有就不跑

---

## Step 0 — 素材采集 + 写作计划

### 做什么

获取今天的写作素材，构思一个具体的写作框架，生成一份轻量写作计划（`Plan.md`）供 Step 1 直接使用。**这一步不弹确认**——框架是否站得住，留到 Step 1 看到真实文字时一并判断，那时候用户才有真实的直觉去评价。

### Agent 操作

**① 获取素材**

1. 确认日记来源：
   - 用户明确说了"用昨天/某天/某个日期/某篇的日记"或提到了具体文件名 → 读取对应的 `diary/` 文件
   - 用户没指定 → 检查 `diary/YYYY-MM-DD.md` 或 `diary/YYYY-MM-DD.txt`（今天日期）是否存在（优先 `.md`）
     - **存在** → 读取全文作为素材
     - **不存在** → 问用户："今天有什么想记录的？一两句话就行。"
2. 用户口头输入后，将内容写入 `diary/YYYY-MM-DD.md`（纯文本，无需 frontmatter）

**② 素材厚度检查**

检查素材：有没有至少一个**具体画面/感受/细节**？
- **有** → 进入框架构思
- **没有** → 方向性追问，不要泛泛地问"要不要多说两句"：
  > "这条比较单薄，要不要多说说——当时具体在哪？看到/听到/摸到了什么？身体或情绪有什么反应？"
  用户说"就这么短"→ 按短的写，不要硬凑成文

**③ 框架构思**

1. 读 `references/framework_cards.md` 的几种参考模式找感觉，不需要强行归为一类——素材同时带有多种模式的影子时，参考文件里"多种模式同时命中时怎么办"的处理原则
2. 直接落地一个具体的 3 拍框架——"这篇文章第一拍写什么、第二拍写什么、第三拍写什么"，不需要先给这篇素材贴一个类型标签再倒推框架

**④ 定工作标题，创建项目目录**

1. 从内容提炼一个工作标题，格式为「生活中的美好：XX」。Step 1 定稿时标题可以微调，但项目目录名不必跟着改名
2. 创建项目目录：

```bash
mkdir -p To-be-used/Project_Daily_标题/
```

**⑤ 写 Plan.md**

写入 `To-be-used/Project_Daily_标题/Plan.md`（纯文档，不接入脚本校验，Agent 自己参考用，不等待用户确认），格式：

```markdown
# 写作计划：生活中的美好：帮邻居收快递

- 素材来源：diary/2026-07-19.md（或 .txt）
- 框架落地：
  1. 画面：早上出门看到邻居快递被雨淋了半截
  2. 反应：顺手收进屋，拍照发给他
  3. 收尾：停在"心里暖了一下午"这个感受里
- 篇幅感觉：短
- 子标题候选：XX / XX（从素材里找自然的分段线索，≥500 字必填）
- 标签方向：日行一善
```

写完直接进入 Step 1，不停顿等待。

### 产出

- `diary/YYYY-MM-DD.md`（落盘）
- `To-be-used/Project_Daily_标题/Plan.md`

## Step 1 — 成文 + 用户确认（★ 唯一门禁）

### 做什么

读取 `Plan.md` 的框架落地 → 按此写作 → L1 自查 → 落盘 → 脚本验证 → 引导用户确认。**这是流程里唯一一道人工门禁**——用户看到的是真实文字，能凭直觉判断行不行；框架写得合不合适，也在这里一并体现，不合适就在这一步直接改。

### 写作要求

- **素材优先**：日记是素材，不是成品。Agent 要在两个方向上同时用力：
  - **内容忠实**：事实、场景、关键措辞、语气——从日记来，不编不造，不为制造叙事张力而放大冲突
  - **语言润色**：日记写给自己看，有跳跃、省略、节奏松散。Agent 要调整句子节奏、补充自然过渡、让段落流动起来。润色的是表达，不是内容——不说日记没有的话，但说得更流畅自然。具体技法参考 `references/polish_techniques.md`
- **结构约束**：按 `Plan.md` 里落地的 3 拍框架组织内容，遵守 `framework_cards.md` 里相关参考模式的「特有提醒」和「通用底线」
- **子标题**：文章超过 500 字时，至少设计 1-2 个子标题（`##` 格式）做分段路标。子标题从内容中提炼关键词，简短自然（2-6 个字），不做口号式概括。500 字以下，如果内容有明显层次递进，也可以用一个子标题来标记转折——判断标准是内容结构，不只是字数
- **篇幅**：遵循参考模式的篇幅感觉（短/中等/中长），按素材本身的节奏走——有东西就写，写完就停，不凑不截。详见 `framework_cards.md` 篇幅原则
- **风格**：第一人称、口语化、体感叙事。参考 `../../wechat-writer/knowledge/style_guide.md`
- **标题**：从内容提炼关键词，格式为「生活中的美好：XX」。用户可要求自定义标题
- **标签**：从素材中提炼 1-3 个标签（如：日常片段、读书分享、微习惯、感官觉知、日行一善、AI 实践 等）
- **唯一硬门禁——人机边界**：不编造场景细节、对话、未说过的观点。这条和 `wechat-writer` 共享同一条纪律，不因为轻量而放松

### 金句识别

写作时留意全文最有力量的 1-3 句话。判断标准：
- 读完后印象最深的那一句
- 能独立成义、截图发朋友圈也成立的那一句
- 不是信息描述，而是感受/洞察/转折

识别出的金句写入 `_temp_daily.json` 的 `gold_quotes` 字段（字符串数组）。这些句子在 HTML 中会自动加粗显示。素材太轻、没有值得标记的句子就不填。

### ⛔ L1 自查 9 条（写完必做，逐条过，不过就改）

| # | 检查项 | 怎么查 |
|---|--------|--------|
| 1 | **禁词** | 有没有「说白了」「本质上」「值得注意的是」「不可否认」「毋庸置疑」「总而言之」「情绪价值」「狠狠」？→ 有就删/换 |
| 2 | **冒号** | 正文中有没有中文冒号「：」？→ 改成逗号或分句。标题中的「生活中的美好：XX」除外 |
| 3 | **破折号** | 有几个「——」？→ ≥ 3 个就删到 2 个以内 |
| 4 | **排比对仗** | 有没有「A 不是 B，是 C」式排比/对仗句？→ 拆掉 |
| 5 | **人机边界** | 有没有编造素材中没有的场景细节、对话、观点？→ 有就删 |
| 6 | **朗读感** | 读一遍全文：听起来像说话还是像写稿？→ 像写稿就改，找到两处把句号改逗号 |
| 7 | **金句自检** | 有没有 1-3 句话值得标记为金句？→ 有就写入 JSON 的 `gold_quotes`。没有就不填，不求凑数 |
| 8 | **日记对照** | 分三个维度查：① **内容**——有没有日记里没有的概括（把"不太愿意"写成"一家人都不开心"）？有没有放大冲突？→ 有就删。② **语气**——润色后的人称、态度、说话方式变了没有？（比如"弟弟"改成了"孩子"、随意的口吻变成了正式口吻）→ 变了就改回来。③ **氛围退化**——有没有把日记里的具体行为，替换成「气氛」「氛围」等抽象判断？日记说「弟弟不愿意，开始闹腾」，你有没有写成「气氛紧张」？→ 有就改回具体行为。句子流畅度和节奏的改善不是语气变化，是应该做的 |
| 9 | **美感自检** | 挑改动最大的一句，对照日记原句，说出用了 `polish_techniques.md` 哪条技法、为什么改后更有画面感。说不出来就换一条真正有效的技法重新润色 |
| 10 | **结构连贯** | 读前三段和后三段——听起来像同一篇文章、同一个人吗？有没有一段突然换了人称或口气（从"我"跳到"你该"）？→ 有就回到 Plan 重定主线，把不兼容的内容裁掉或转换口吻 |
| 11 | **指令口气** | 文中有没有直接从日记搬过来的「你应该/你可以/邀请你/盘点一下/聚焦一个/从今天开始做X」式指令？→ 有就转换成个人思考口吻：把"你"换成"我"，把指令换成"我在想/在试X"。参考 `polish_techniques.md` 技法 6 |

> L1 自查不通过（第 1-6、8-11 条）→ 就地修改 → 再查 → 通过才落盘。第 7 条（金句自检）没有就不填，不算不通过。

### 落盘 + 验证

**⛔ HARD STOP：自查通过后，先落盘，再验证，再告知用户。禁止在对话中直接输出草稿全文。**

1. 项目目录已在 Step 0 创建，在其中落盘 2 个文件（与 `Plan.md` 同目录）：

| 文件 | 内容 |
|------|------|
| `To-be-used/Project_Daily_标题/Draft.md` | 标题 + 标签 + 正文（Markdown，人类可读） |
| `To-be-used/Project_Daily_标题/_temp_daily.json` | `{title, date, body_markdown, excerpt, tags, img_dir}` |

`Draft.md` 格式：

```markdown
# 生活中的美好：帮邻居收快递

> 标签: 日行一善, 日常片段

早上出门看到邻居的快递被雨淋了半截，顺手帮他收进屋。
放门口拍了张照发给他。他回了个"谢谢！"，加了个笑脸。
顺手的事，心里却暖了一下午。
```

`_temp_daily.json` 格式见下方「脚本契约」。

2. **调用 check_draft.py 验证**：

```bash
PYTHONIOENCODING=utf-8 python .claude/skills/wechat-daily/scripts/check_draft.py To-be-used/Project_Daily_标题/
```

- ✅ pass → 进入用户确认
- ❌ fail → 按提示修复后重跑，不通过不能进用户确认

3. **⛔ 告知路径，禁止输出全文**：

> 📝 草稿已写入：`To-be-used/Project_Daily_标题/Draft.md`
> 请打开文件查看，没问题说「发」，有问题直接说。

4. **重复防呆提醒**：扫一眼 `knowledge/daily_article_index.md` 最近 7-10 条。如果连续 5 篇以上主题高度集中（如全是"读书分享"），提醒一句：

   > 对了，最近 5 篇都是读书分享，今天这篇也是，确认继续吗？

   用户说"对，就是想接着写"就过。不强制。

5. **等待用户回复**

### 用户可选操作

| 用户输入 | Agent 行为 |
|----------|-----------|
| "发" / "OK" / "可以" / "没问题" 等 | 进入 Step 2 |
| "改一下 XXX" / "标题改成 YY" 等 | 修改 Draft.md + _temp_daily.json，重跑 check_draft.py，告知文件已刷新，重新等待确认 |
| "不发了" / "算了" | 放弃，素材保留在 `diary/`，流程终止 |

### 产出

- `To-be-used/Project_Daily_标题/Draft.md`
- `To-be-used/Project_Daily_标题/_temp_daily.json`

## Step 2 — 配图

### 做什么

直接让用户选择配图模式，复用 wechat-director 配图能力。跳过「要不要图」的二次确认。

### Agent 操作

1. 用户确认草稿后，直接给出模式选择：

   > "选择配图模式：
   >  A. **完整模式** — AI 生成封面 + 侧边栏
   >  B. **简单模式** — 你提供封面图，AI 只生成侧边栏
   >  C. **跳过配图** — 直接发布"

2. 用户选 A → 进入 wechat-director 完整流程（见 `.claude/skills/wechat-director/SKILL.md`），daily 的差异：
   - 默认只设计 Part A（封面）+ Part B（侧边栏），不做 Part C 内文配图（daily 篇幅短）
   - 侧边栏底色固定为琥珀金 `#D4A854`（不查内容支柱表）
   - **Part A 根据内容判断 IP 形象**：遵循 wechat-director 的 IP 判断规则——画面主体是作者本人（写作、思考、运动等场景）→ 标注 `IP: Yes`，prompt 中描述 IP 角色；抽象概念/纯物体/第三方人物 → 标注 `IP: No`。不再一刀切强制使用 IP
3. 用户选 B → 进入 wechat-director 简单模式。预检封面图后，只设计 Part B 侧边栏
4. 侧边栏文字与装饰规则：完全遵循 `.claude/skills/wechat-director/references/sidebar_design_system.md`
5. 生成完成后，图片落入 `To-be-used/Project_Daily_标题/img/`，分镜写入 `Storyboard.md`
6. 用户选 C → 跳过，`img_dir` 留空，进入 Step 3

### 产出

- `img/` + `Storyboard.md`（如有配图）

## Step 3 — 发布 + 选题雷达

### 做什么

调用 `archive_daily.py` 一键发布归档，然后扫描 `diary/` 反哺选题雷达。

### Agent 操作

**① 发布**

1. 如有配图，更新 `_temp_daily.json` 中的 `img_dir` 为 `"img"`
2. 运行：

```bash
PYTHONIOENCODING=utf-8 python .claude/skills/wechat-daily/scripts/archive_daily.py To-be-used/Project_Daily_标题/_temp_daily.json
```

3. ⛔ 发布完成后告知文件路径，**不要输出全文**：

> ✅ 已发布：`published/YYYYMMDD_标题.md`
> 微信编辑器 HTML：`published/YYYYMMDD_标题.html`

### 脚本自动完成

1. 读取 JSON → 组装正文
2. 追加 bio footer（文末个人 IP 介绍，从 `wechat-writer/references/bio_footer.md` 读取）
3. 写入 `published/YYYYMMDD_标题.md`（含 frontmatter：title/date/excerpt/cover/tags/status）
4. 封面图处理：复制 `img/` → `published/img/`，自动选封面（cover-combined > cover-main）
5. 生成 `published/YYYYMMDD_标题.html`（微信编辑器 HTML）
6. 更新 `knowledge/daily_article_index.md`（daily 独立索引）
7. 项目归档：`To-be-used/Project_Daily_标题/` → `conductor/archive/YYYYMMDD_Daily_标题/`
8. 历史清理：将 `published/` 和 `diary/` 中非当天的文件移入 `history/YYYY-MM/`

### ② 选题雷达扫描

1. 读取 `topic_radar_pool.md`，记下已有的"来源"字段，跳过已记录过的日期
2. 扫描 `diary/` 下最近 7 天的 `.md` 和 `.txt` 文件
3. 对每条素材问判断句：

   > 是否包含"一个可以脱离具体情境、迁移给别人用的步骤/框架/判断标准"？

   - **命中** → 追加到「选题候选」区块，标注方向 + 成熟度
   - **不命中** → 跳过

4. 顺带捕获：当天素材中的隐喻苗头/可复用金句 → 追加到「素材库候选」区块
5. 追加格式（遵循 `wechat-writer/references/io_schema.md` 的雷达池结构）

### 汇报

一句话：

- 无候选："雷达扫描完毕，今天没有新的深挖候选。"
- 有候选："发现 N 个选题候选已写入雷达池：[日期] 候选：XX → 方向：XX，成熟度：XX。"

### 产出

- `published/YYYYMMDD_标题.md`
- `published/YYYYMMDD_标题.html`
- `published/img/`（如有配图）
- `knowledge/daily_article_index.md` 更新
- `conductor/archive/YYYYMMDD_Daily_标题/`（项目归档）
- `topic_radar_pool.md` 追加条目（如有）

## 脚本契约

### `_temp_daily.json` 格式

```json
{
  "title": "生活中的美好：帮邻居收快递",
  "date": "2026-07-19",
  "body_markdown": "早上帮邻居把快递收进屋。顺手的事，心里却暖了一下午。",
  "excerpt": "早上帮邻居收快递，顺手的事，心里却暖了一下午。",
  "tags": ["日行一善"],
  "img_dir": "",
  "gold_quotes": ["顺手的事，心里却暖了一下午。"]
}
```

字段说明：
- `title`：完整标题，已是「生活中的美好：XX」格式，脚本不再加工
- `date`：`YYYY-MM-DD`，省略则用今天
- `body_markdown`：正文 Markdown，不含 frontmatter、不含标题行
- `excerpt`：一句话摘要，可省略
- `tags`：字符串数组，可省略
- `img_dir`：相对 JSON 所在目录的图片文件夹路径（如 `"img"`），没有图就留空字符串
- `gold_quotes`：金句数组（可选，字符串数组）。从正文中摘出 1-3 句最有力量的句子，HTML 渲染时自动加粗。没有值得标记的句子就留空数组或不填
